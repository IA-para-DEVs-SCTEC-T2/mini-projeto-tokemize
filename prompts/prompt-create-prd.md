Analise o contexto do projeto e gere um arquivo `prd.md`.

Com base em tudo que foi especificado e implementado até agora no projeto Tokemize,
gere um arquivo PRD.md (Product Requirements Document). 
O documento deve ser um Product Requirements Document completo e profissional, contendo:

- Visão geral e objetivo do produto
- Problema que resolve
- Personas envolvidas
- Público-alvo
- Funcionalidades principais (o que cada módulo do pipeline faz)
- Fluxo de uso do sistema (do usuário até o LLM)
- Requisitos técnicos e restrições
- Requisitos funcionais
- Requisitos não funcionais
- Regras de negócio
- Critérios de aceite por funcionalidade
- Próximos passos / roadmap inicial

O PRD deve ser escrito em Markdown bem estruturado, com títulos claros e critérios de aceite detalhados.

Salve o arquivo em: docs/PRD.md
